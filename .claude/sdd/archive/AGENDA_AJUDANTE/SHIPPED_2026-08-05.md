## Summary

A agenda-lista do ajudante ganhou uma visão de calendário mensal, aviso de conflito (dias com 2+ diárias, ou uma diária caindo num dia marcado como indisponível) e blocos de disponibilidade — o ajudante marca/desmarca dias em que não pode trabalhar. Os blocos são privados: uma tabela `bloqueio_agenda` com RLS de dono garante que ninguém mais os lê. A feature evolui o que já existia (a `/agenda` já listava as diárias aceitas) em vez de recriar, sem adicionar nenhuma dependência.

## Lessons Learned

### Process

- **Ler o código antes de projetar** (de novo o que mais rendeu na sessão): a `/agenda` já existia como lista, então a feature virou *evoluir*, não *criar* — o escopo real era calendário + conflito + blocos sobre uma base pronta.
- Feature pequena e sem dependência nova → build de uma tacada (fundação + integração juntas), sem os 2 estágios que o chat/mapa exigiram.

### Technical

- **Nem tudo precisa de `dynamic ssr:false`**: o mapa (Leaflet) precisou porque usa `window`; o calendário é só um grid de datas, SSR-safe — reconhecer isso evitou complexidade desnecessária.
- **Regra de conflito numa função pura** (`diasEmConflito`) rendeu o teste-âncora: rápido, determinístico, sem DB nem browser (5 casos).
- **Server component como prop de client component**: a lista (server) foi passada como prop para o `AgendaView` (client, que faz o toggle) — padrão do App Router que evitou reescrever a lista no cliente.

### Communication

- A decisão "conflito por dia" (a vaga não tem `hora_fim`) foi registrada desde o brainstorm — alinhou a expectativa antes do código.

### Tools & Libraries

- **O vitest do projeto não tem alias `@/`**: o teste falhou no import `@/lib/agenda-conflitos` e o fix foi usar caminho relativo (`../lib/...`), como os testes vizinhos. Lição: seguir a convenção de import dos testes existentes, não a do app.
- **`test:integration`** provou a RLS de dono do bloqueio contra o banco real (1 caso), e o conector MCP aplicou a migration aditiva + advisors (sem ERROR novo).
